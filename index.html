How to use this guide

This guide assumes you are studying databases for the first time. Do not try to memorize every query as a picture. For each question, follow the same routine:

  1. Read the question and identify exactly what result it wants.
  2. Find the table that contains the result column.
  3. Find the other tables needed to connect or filter the result.
  4. Choose the columns after SELECT.
  5. Connect tables using their matching key columns.
  6. Add the required condition using WHERE, a subquery, or an aggregate function.
  7. Read the final query from top to bottom and check that every condition matches the question.
Important: The SQL code and questions are based on the uploaded labs. Explanations are expanded in simple English to help a first-time learner understand why each step is needed.

SQL basics before the labs

Database

A database is an organized place that stores related information. Example: a Store database can store customers, orders, and products.

Table

A table stores one type of information in rows and columns. Customer is a table; each customer is one row.

Row / Record

One complete item inside a table. One row in Customer represents one customer.

Column / Field

One property stored for every row. CustomerID and CustFirstName are columns.

Primary Key (PK)

A column, or group of columns, that uniquely identifies a row. It cannot contain duplicate key values.

Foreign Key (FK)

A column that points to a key in another table. It creates a relationship between tables.

SQL commands you will see

CREATE DATABASE Store;
CREATE DATABASE creates a new database. The semicolon ends the statement.
CREATE TABLE Customer (...);
CREATE TABLE creates a table and defines its columns and constraints.
INSERT INTO Customer VALUES (...);
INSERT INTO adds a new row to a table.
SELECT column FROM table;
SELECT reads data. FROM says where the data comes from.
WHERE condition
WHERE filters rows. Only rows that satisfy the condition are returned or affected.
JOIN ... ON ...
JOIN combines related rows from two tables. ON tells SQL which columns match.
COUNT(*) / MAX(x) / AVG(x)
Aggregate functions calculate one result from multiple rows: count, maximum, or average.
CREATE PROCEDURE / CREATE FUNCTION
A procedure is a saved set of SQL statements that you execute. A function is a saved operation that returns a value or a table.
SQL Server note: The labs use SQL Server / T-SQL syntax. For example, variables start with @, GO separates batches in SQL Server tools, and dbo. is a common schema prefix.

5. Retrieve the products name, ID and its quantityQuestion
What does the question want?

Show each product's ID and name together with the quantity recorded for it in Order_Details. The product information is in Product, but the quantity is in Order_Details, so the two tables must be connected.

How to think about it — step by step

  1. The requested output columns are PID, PName, and Quantity.
  2. PID and PName come from Product.
  3. Quantity comes from Order_Details.
  4. Connect Product.PID to Order_Details.ProductID so each quantity is matched with the correct product.

SQL solution

SELECT PID, PName, Quantity
FROM Product, Order_Details
WHERE Product.PID = Order_Details.ProductID;

Line-by-line explanation

SELECT PID, PName, Quantity
Chooses the three columns that the question asks to display.
FROM Product, Order_Details
Uses both tables because the requested columns are split between them.
WHERE Product.PID = Order_Details.ProductID
Matches each product row with its order-details row. Without this condition, unrelated rows could be combined.
6. Retrieve all the Customers ID and First Name that have their order delivered.Question
What does the question want?

Return the customer ID and first name for customers whose order status is Delivered. The lab solution also displays OrderID and OrderStatus, so those two columns are included in the original answer.

How to think about it — step by step

  1. The customer ID and first name are in Customer.
  2. The order status and order ID are in Orderr.
  3. Connect the two tables using Customer.CustomerID = Orderr.CID.
  4. Keep only rows where OrderStatus equals the exact text 'Delivered'.
  5. The lab provides two valid styles: comma join with WHERE, or JOIN with ON.

SQL solution

SELECT CustomerID, CustFirstName, OrderID, OrderStatus
FROM Customer, Orderr
WHERE CustomerID = CID AND OrderStatus = 'Delivered';

-- Alternative solution from the lab
SELECT CustomerID, CustFirstName, OrderID, OrderStatus
FROM Customer JOIN Orderr
ON CustomerID = CID
WHERE OrderStatus = 'Delivered';

Line-by-line explanation

SELECT CustomerID, CustFirstName, OrderID, OrderStatus
Selects the customer ID, first name, order ID, and order status.
FROM Customer, Orderr
Uses the customer table and the order table.
WHERE CustomerID = CID
Connects a customer's ID to the customer ID stored in the order row.
AND OrderStatus = 'Delivered'
Adds a second condition: only delivered orders are returned.
JOIN Orderr ON CustomerID = CID
The alternative syntax performs the same table connection using JOIN and ON.

Lab 2 — Complex Queries

Subqueries, IN, aggregate functions, DISTINCT, JOIN, and filtering related records in the Company schema.

1. Retrieve the names of the dependentsthat have employee relatives working in the research department.Question
What does the question want?

The question wants the names of dependents whose related employee works in the department named Research. The name we must display is in Dependent.Dependent_name. However, to know whether that dependent belongs to an employee in Research, we must check the employee's department.

How to think about it — step by step

  1. Start with Dependent because the required output is Dependent_name.
  2. Dependent.Essn stores the SSN of the employee related to that dependent.
  3. Find the SSN values of employees who work in Research.
  4. To find those employees, connect Dept to Employee using Dept.Dnumber = Employee.Dno.
  5. Use IN to keep only dependents whose Essn is in the list of Research employees' Ssn values.

SQL solution

SELECT Dependent_name AS 'Dependents of Research Dept Employees'
FROM Dependent
WHERE Essn IN
(
    SELECT Ssn
    FROM Dept, Employee
    WHERE Dept.Dnumber = Employee.Dno
      AND Dept.Dname = 'Research'
);

Line-by-line explanation

SELECT Dependent_name
Displays the dependent's name. This is the information requested.
AS 'Dependents of Research Dept Employees'
Gives the output column a readable heading. AS changes the displayed column label, not the stored column name.
FROM Dependent
Starts from the table that contains dependent names.
WHERE Essn IN (...)
Keeps a dependent only when its employee SSN appears in the list returned by the subquery.
SELECT Ssn
The inner query returns employee SSNs.
FROM Dept, Employee
The inner query needs both department details and employee details.
WHERE Dept.Dnumber = Employee.Dno
Connects each employee to the department where that employee works.
AND Dept.Dname = 'Research'
Filters the connected rows to the Research department only.
Remember the two levels: the inner query finds the employee SSNs in Research; the outer query uses those SSNs to find dependent names.
2. Retrieve the maximum salary of the employees working on the project that is located in ‘Zamalek’.Question
What does the question want?

Find the highest salary among employees who work on a project whose location is Zamalek. The salary is in Employee, project location is in Project, and the employee-project link is in Works_On.

How to think about it — step by step

  1. Find the project numbers for projects located in Zamalek.
  2. Use Project.Plocation = 'Zamalek' and return Pnumber.
  3. Find employees linked to those projects through Works_On.Pno.
  4. Connect the employee SSN to Works_On.Essn.
  5. Use MAX(Salary) to return the highest salary among the matching employees.

SQL solution

SELECT MAX (Salary) AS 'Max salary of employees working on projects in Zamalek'
FROM Employee, Works_On
WHERE Essn = Ssn
  AND Pno IN
  (
      SELECT Pnumber
      FROM Project
      WHERE Project.Plocation = 'Zamalek'
  );

Line-by-line explanation

SELECT MAX (Salary)
MAX calculates the largest salary among the rows that pass the WHERE conditions.
FROM Employee, Works_On
Uses employee salary and the table that records which employees work on which projects.
WHERE Essn = Ssn
Matches Works_On.Essn with Employee.Ssn.
AND Pno IN (...)
Keeps only employee-project rows whose project number is in the subquery result.
SELECT Pnumber FROM Project
Returns project numbers.
WHERE Project.Plocation = 'Zamalek'
The inner query selects only projects located in Zamalek.
The lab also provides a second valid solution using Employee as the outer table and Project plus Works_On inside the subquery. Both approaches aim to calculate the same maximum salary.
3. Retrieve the name of the project that have the maximum number of hours.Question
What does the question want?

Return the project name for the row or rows whose recorded Hrs value is the largest in Works_On. The project name is in Project, while Hrs is in Works_On.

How to think about it — step by step

  1. Use Project and Works_On because the name and hours are in different tables.
  2. Connect Project.Pnumber to Works_On.Pno.
  3. Find the maximum Hrs value with a subquery.
  4. Keep only joined rows where Works_On.Hrs equals that maximum value.
  5. Display Pname.

SQL solution

SELECT Pname AS 'Project with maximum hours'
FROM Project JOIN Works_On
ON Project.Pnumber = Works_On.Pno
WHERE Works_On.Hrs =
(
    SELECT MAX (Hrs)
    FROM Works_On
);

Line-by-line explanation

SELECT Pname
Displays the project name.
AS 'Project with maximum hours'
Changes the output heading to explain what the value represents.
FROM Project JOIN Works_On
Combines project information with employee project-hour records.
ON Project.Pnumber = Works_On.Pno
Matches each work record to its project.
WHERE Works_On.Hrs = (...)
Keeps only records whose hours equal the maximum hours.
SELECT MAX (Hrs) FROM Works_On
Calculates the largest Hrs value in the Works_On table.
4. Retrieve the department names without duplication where the working employees have female dependents.Question
What does the question want?

Find departments that have employees who have at least one female dependent. Show each department name only once, even if several employees in the same department satisfy the condition.

How to think about it — step by step

  4. Use IN to keep employees whose Ssn is in that list.

SELECT DISTINCT Dname AS 'Departments having employees with female dependents'
FROM Dept, Employee
WHERE Employee.Dno = Dept.Dnumber
  AND Ssn IN
  (
      SELECT Essn
      FROM Dependent
      WHERE Sex = 'F'
  );

Line-by-line explanation

SELECT DISTINCT Dname
Displays department names and removes duplicate values.
AS 'Departments having employees with female dependents'
Sets a descriptive output heading.
FROM Dept, Employee
Uses department and employee information together.
WHERE Employee.Dno = Dept.Dnumber
Connects each employee to their department.
AND Ssn IN (...)
Keeps employees whose SSN is returned by the inner query.
SELECT Essn FROM Dependent
Returns the employee SSNs stored with dependent records.
WHERE Sex = 'F'
The inner query only includes female dependents.

3. Once the user has entered or passed the product name (ex: tv), you should retrieve this product name and also its description. Then print them out with the alias “The name of the product is TV and its description is Smart TV”.Question
What does the question want?

The procedure receives a product name, finds the matching product, combines its name and description into one output parameter, and prints a sentence. The lab shows two ways: print inside the procedure, or return the output parameter and print it outside.

How to think about it — step by step

  1. Create an input parameter @Pname for the product name.
  2. Create an output parameter to carry the combined text back to the caller.
  3. Find the row in Product where Pname = @Pname.
  4. Combine Pname and Pdescription into the output parameter.
  5. Print the sentence, or declare a variable outside and receive the output parameter.

SQL solution

  3. Identify who receives the permission after TO.
  4. Use PUBLIC when the permission should apply to all users.
  5. Add WITH GRANT OPTION only when the user should be allowed to pass that permission to another user.

SQL solution

-- Example 5: Grant SELECT on Customer to Ahmed
grant select on Customer to [ahmed];

-- Example 6: Grant SELECT on Customer to all users
grant select on Customer to public;

-- Example 7: Grant SELECT to Ali and allow him to grant it to others
grant select on Customer to [ali] with grant option;

-- Example 8: Grant INSERT to Ahmed and allow propagation
GRANT INSERT ON Product TO [ahmed] with GRANT OPTION;

-- Example 9: Grant multiple permissions to PUBLIC
GRANT SELECT, INSERT, DELETE, UPDATE ON Product TO public;
-- Alternative shown in the lab
GRANT ALL ON Product TO public;

-- Example 10: Create a function and grant EXECUTE
CREATE FUNCTION Get_Maximum_Quantity()
RETURNS INT
AS
BEGIN
    DECLARE @Max_Quantity INT;
    SELECT @Max_Quantity = MAX(Quantity)
    FROM Order_Details;
    RETURN @Max_Quantity;
END;

grant execute on dbo.Get_Maximum_Quantity to public;

Line-by-line explanation

GRANT SELECT ON Customer TO [ahmed]
Gives the user ahmed permission to read rows from Customer.
TO public
Gives the permission to all users through the PUBLIC role.
WITH GRANT OPTION
Allows the receiving user to grant the same permission to other users.
GRANT INSERT ON Product TO [ahmed]
Allows ahmed to insert rows into Product.
GRANT SELECT, INSERT, DELETE, UPDATE ON Product TO public
Gives PUBLIC four permissions on Product.
GRANT ALL ON Product TO public
The alternative shown in the lab: grants all available permissions on Product.
CREATE FUNCTION Get_Maximum_Quantity()
Creates a function that returns the maximum order quantity.
MAX(Quantity)
Finds the largest Quantity value in Order_Details.
grant execute on dbo.Get_Maximum_Quantity to public
Allows all users to execute this function.
General pattern: GRANT permission ON object TO user. The word before ON is the permission; the word after ON is the object; the word after TO is the recipient.
Examples 11–13. Revoke permissions from users.Question
What does the question want?

REVOKE removes permissions that were previously granted. The lab demonstrates removing SELECT on Orderr, EXECUTE on a function, and several permissions on Order_Details.

How to think about it — step by step

  1. Identify which permission must be removed.
  2. Identify the object after ON.
  3. Identify the user or role after FROM.
  4. Write REVOKE instead of GRANT.
  5. Keep the permission and object names exactly as required by the question.

SQL solution

-- Example 11: Revoke SELECT on Orderr from PUBLIC
REVOKE SELECT ON Orderr FROM public;

-- Example 12: Revoke EXECUTE on the function from PUBLIC
REVOKE EXECUTE ON dbo.Get_Maximum_Quantity FROM public;

-- Example 13: Revoke four permissions on Order_Details from PUBLIC
REVOKE SELECT, INSERT, DELETE, UPDATE ON Order_Details FROM public;

Line-by-line explanation

REVOKE SELECT ON Orderr FROM public
Removes the SELECT permission on Orderr from PUBLIC.
REVOKE EXECUTE ON dbo.Get_Maximum_Quantity FROM public
Removes permission to execute this function from PUBLIC.
REVOKE SELECT, INSERT, DELETE, UPDATE
Lists the four permissions being removed.
ON Order_Details
Specifies the object whose permissions are being changed.
FROM public
Specifies the recipient whose permissions are being revoked.
Memory pattern: GRANT uses TO; REVOKE uses FROM. GRANT gives permission; REVOKE removes permission.

How to approach any SQL question in the exam

  1. Underline the action word. Create means CREATE. Add means INSERT. Retrieve means SELECT. Calculate the highest means MAX. Count means COUNT. Give permission means GRANT. Remove permission means REVOKE.
  2. Underline the requested output. If the question asks for names, identify the name column. If it asks for a number, decide whether it needs COUNT, MAX, or another calculation.
  3. Find the table containing the output. Start with that table in FROM.
  4. Check whether the other requested information is in another table. If yes, connect tables using the foreign-key relationship shown in the schema.
  5. Translate conditions into SQL. "where", "only", "whose", "located in", and "same as" usually indicate a condition. Use WHERE, AND, IN, or a subquery as needed.
  6. Decide whether the answer is one value or many rows. One value is commonly a scalar function. A set of rows/columns is a table-valued function or SELECT result. A reusable action is a stored procedure.
  7. Check every table and column name. Use the exact names in the schema you are working with: for example Orderr, Order_Details, Pname, and ProductID.
  8. Read the code like a sentence. SELECT what you want FROM where it lives WHERE which rows qualify.
